# docs/lessons/ — 踩坑经验库

> 一库一文件（`<lib>.md`），平台/部署坑也各一文件（如 `electron.md`）。
> AI 使用某库写代码前，**该库的 lessons 文件存在则必读**。

## 写入触发器（常驻规则）

凡"AI 因对某库/平台的错误认知出错、后被修正"的事件，修正后必须申请追加一条。

## 条目格式（一条 ≤5 行）

```
### <一句话坑名>
- 症状：<什么报错/什么异常行为>
- 根因：<对库的什么错误假设>
- 规则：<今后必须怎么做（具体禁令措辞）>
- 元：<库名@版本 | 日期 | 候选毕业方向：lint / 封装层 / 无>
```

## 同意机制

条目先落为未提交 diff，会话收尾批量结算，用户确认后才 commit。被拒条目直接丢弃。

## 压缩与毕业

- 单文件超 20 条 → 下次会话先合并同类、删过期条目（也走确认）
- 升某库大版本 → 重审该库全部条目（坑可能已被上游修复）
- 可落成 lint/CI 规则的 → 毕业成硬约束，从本库删除
- 反复出现的第三方调用姿势问题 → 收进封装层，从本库删除
- 毕业一条删一条：文档保持精瘦，约束形态持续升级

层 A · 内嵌 Postgres

目标：本地跑 Postgres 方言，迁 Supabase 只换连接。

@electric-sql/pglite

当前推荐 层 A

定位：Electric 的 WASM Postgres，在浏览器、Node、Bun、Deno 进程内跑完整 Postgres，无需安装服务。官方说明「不像先前方案那样套 Linux VM，就是 WASM 里的 Postgres」。

  • 持久化：Node/Bun 目录（NodeFS）；浏览器 idb://（IndexedDB）；全平台内存 memory://。官方当前建议浏览器用 IndexedDB，因 OPFS AHP 不被 Safari 支持。
  • IndexedDB 按「整文件 blob」flush，「每次查询后可能数毫秒」；提供 relaxedDurability：先返回结果，再异步 flush。
  • Live query 扩展：@electric-sql/pglite/live 的 live.query / incrementalQuery / changes。
  • 限制（README）：single user / single connection。
  • 许可证正文：可在 Apache-2.0 与 PostgreSQL License 中二选一。

官方入门（pglite.dev/docs，2026-08-30 抓取）

import { PGlite } from '@electric-sql/pglite'

const db = new PGlite('./path/to/pgdata')     // Node 文件
const idb = new PGlite('idb://my-pgdata')     // 浏览器 IndexedDB
await db.query(`select 'Hello world' as message;`)
适合 Classolo 吗 适合，作为 P0–P2 主库。这是唯一把「免安装单机 exe + 开发期浏览器可跑 + 迁 Supabase 不改 dialect」三条同时接上的选项。写入策略必须按官方口径做：Electron 用 NodeFS；开发期 IndexedDB 打开 relaxedDurability；转写流先内存缓冲再批量 INSERT，不要每句同步 flush。

层 B · SQLite

原生快，但 Drizzle 要走 sqlite-core，与 Postgres/Supabase 不是同一套 schema。

Agent 框架

分层结论：P0 用单 Agent 轻量工具调用层（Vercel AI SDK）覆盖笔记整理、可对话 Agent 与「工具调用即渲染」；静默课堂 Agent 的状态机先自研薄循环，复杂到需要持久化图时再上 LangGraph.js。不要用编码 CLI harness 当应用内框架，也不要一上来上全栈 Agent 平台。

抓取日 2026-08-30 候选 5 · 全部联网核实 查不到的项标「未核实」 第二轮：Pi 消歧与终审

L1 单 Agent 工具调用层 — streamText / tool calling / 结构化输出 / 流式 reasoning。对应笔记整理器与可对话 Agent。当前推荐：Vercel AI SDK（ai）。

L2 多 Agent / 状态机编排层 — 图、checkpoint、人机中断。对应静默课堂 Agent 若演变成可恢复长流程。候选：LangGraph.js；P0 不必装。

L3 极简自研循环 — 仅当 SDK 的 tool 事件对不上自研渲染协议时，用 100 行左右的「调模型 → 执行 tool → 发 RenderMessage」循环包一层。不要从零实现 provider 适配。

import { streamText, tool, Output } from "ai";
import { createOpenAICompatible } from "@ai-sdk/openai-compatible";
import { z } from "zod";

const model = createOpenAICompatible({
  name: "classolo",
  apiKey: process.env.CLASSOLO_API_KEY,
  baseURL: "https://api.provider.com/v1",
})("user-chosen-model");

const result = streamText({
  model,
  reasoning: "medium",
  tools: {
    showImage: tool({
      description: "在渲染区展示检索到的图片",
      inputSchema: z.object({ query: z.string(), url: z.string() }),
      // 无 execute：把 tool call 交给前端，按 CRP 发 RenderMessage
    }),
  },
  output: Output.object({
    schema: z.object({
      outline: z.array(z.object({ title: z.string(), bullets: z.array(z.string()) })),
    }),
  }),
  prompt: "根据最新转写增量更新笔记大纲。",
});

示例按官网 createOpenAICompatible、tool()、Output.object、reasoning 拼装，展示 Classolo 用法，不是官网逐字拷贝的单一片段。

适合 Classolo 吗？适合，作为 L1 默认。 三个 AI 角色都是「一个模型 + 一组 tool + 结构化/流式输出」；渲染协议可以直接把每个模块注册成 tool。Gateway 默认路径必须避开。

Pi Agent · @mariozechner/pi-* / @earendil-works/pi-*

定位：分层 Agent harness。上层是终端编码 CLI，中层是可嵌入的 agent loop，下层是多 provider LLM API。不是 Next.js 应用框架，也不是 LangGraph 那种图编排器。

用户点名查证结论（2026-08-30）

npm 与 GitHub 上确实存在这套 TypeScript Agent 工具箱。作者 Mario Zechner（badlogic）。仓库 github.com/badlogic/pi-mono 现重定向到 earendil-works/pi（99,148 stars，12,300 forks，MIT，pushed 2026-08-29）。官网 README 自称 “Pi agent harness”，包分层：

import { StateGraph, StateSchema, START, END } from "@langchain/langgraph";
import { z } from "zod/v4";

const State = new StateSchema({
  topic: z.string(),
  joke: z.string(),
});

const graph = new StateGraph(State)
  .addNode("refineTopic", (state) => {
    return { topic: state.topic + " and cats" };
  })
  .addNode("generateJoke", (state) => {
    return { joke: `This is a joke about ${state.topic}` };
  })
  .addEdge(START, "refineTopic")
  .addEdge("refineTopic", "generateJoke")
  .addEdge("generateJoke", END)
  .compile();

for await (const chunk of await graph.stream(
  { topic: "ice cream" },
  { streamMode: "updates" }
)) {
  console.log(chunk);
}

B. earendil-works/pi 架构与可嵌入性

当日 GitHub packages/ 目录：ai、agent、coding-agent、tui、telemetry、protocol、client、server、session-backends、evals。没有 web / web-ui。

  • @earendil-works/pi-ai — 多 provider LLM 层（OpenAI / Anthropic / Google / Bedrock / OpenRouter / Ollama 等）。只收录支持 tool calling 的模型。OpenAI 兼容走 api: "openai-completions" + baseUrl + compat.thinkingFormat。流式事件含 thinking_start/delta/end、text_delta、toolcall_*。
  • @earendil-works/pi-agent-core — 可嵌入 runtime。Agent / agentLoop：tool 执行、校验、事件流、transformContext（压缩入口）、steering/follow-up 队列、beforeToolCall / afterToolCall。动态 agent.state.tools = [...]。自定义 tool 的 execute(..., onUpdate) 可流式进度。schema 是 TypeBox。
  • @earendil-works/pi-coding-agent — 终端编码 CLI + 官方嵌入 SDK（createAgentSession）。默认四工具 read / write / edit / bash。session 树（单文件多分支、/tree /fork）、compaction、skills（Agent Skills / SKILL.md 渐进披露）、TypeScript extensions、pi install packages。四种模式：interactive / print-JSON / RPC / SDK。
  • @earendil-works/pi-tui — 差分渲染 TUI，给 CLI 用，不是 React。
  • pi-web？ — @earendil-works/pi-web-ui 曾是 Lit web components，npm latest 停在 0.75.3（2026-05-18），仓库已 chore: remove web-ui workspace。当前有 experimental @earendil-works/pi-server 与 CBOR 传输的 pi-client；有过 pi web GUI PR，但当日 main 的 packages/ 没有独立 web 包。不是给 Next/React 用的 UI 层。
  • Skills / extensions — skills 在 coding-agent 层（扫描 SKILL.md、system prompt 只放名称+描述、按需 read）；extensions 是跑在 pi 进程里的 TS 模块（registerTool、生命周期 hook、TUI）。这是 P1「skills 注册」想抄的机制，但绑定的是 CLI 工作区，不是渲染模块表。

作为可嵌入库做非编码课堂 Agent：行不行

技术上能嵌。官方把 SDK 模式写成「Embed Pi in your apps」，旗舰实例是 OpenClaw（消息网关里 createAgentSession()，不 spawn 子进程）。pi-agent-core 可单独 npm install，浏览器需 streamProxy 走后端。

动态 tool 注册有。赋值 agent.state.tools。课堂渲染模块表可以每轮塞进去。
自定义 tool 流式 onUpdate有。适合「工具进度」；也可以在 execute 里发 CRP。README 示例里 tool 总是带 execute；「无 execute、把 call 交给 React」不是一等 API（未在文档中核实为可选字段）。
结构化输出core 无 Output.object。社区/SDK 文档用 terminating tool 模拟。笔记整理器要流式 JSON 大纲，得自己做 schema+校验，或把大纲做成 tool 参数。
thinking 流有。thinkingLevel + thinking_delta。兼容端点靠 compat.thinkingFormat（openai / qwen / deepseek / …），比 AI SDK 的顶层 reasoning 更细，也更要手配。
event 流接 React能接，但是 TUI 事件模型（message_update / tool_execution_*）。没有 useChat、没有 UIMessage parts、没有 Generative UI。Electron 里应放在 Node/main；pi-coding-agent 还依赖原生 @silvia-odwyer/photon-node，不要进 renderer。接 CRP 的成本是自写一层 event→RenderMessage 适配器。

嵌入结论：可以当 Node 里的 agent loop 用；用来驱动「工具即渲染 + React 工作台」要自建 UI 协议层，且没有流式结构化输出原语。这不是「嵌不进去」，是「嵌进去之后 Classolo 仍要写 AI SDK 已经写好的那一层」。

好处（客观）与用在 Classolo 的代价

好处（属实）：作者把上下文工程做成产品——极短 system prompt、session 树、可定制 compaction、skills 渐进披露、extensions 热加载、15+ provider 与中途换模型、MIT、不绑 Vercel/OpenAI 云、四种运行模式、供应链上强调 --ignore-scripts。Thomas Wiegold 的评测把 SDK 说成「真正值得关心的部分」：可以限制成你自己的 tool 集，丢进 cron。OpenClaw 证明这套能撑一个多通道助手产品。

代价（属实）：TypeBox 而非 Zod（与 Classolo 其余栈不一致）；文档心智是 CLI 用户与 coding-agent SDK，不是 Next App Router；包仍为 0.84.x，2026-05 迁 scope 后约三个半月十几个 minor（0.74→0.84），API 迁移成本高（旧 getModel 全局 API 已改 createModels()）；pi-agent-core 直连 pi-ai+pi-telemetry+一串云 SDK（第一轮 resolved 93 包）；coding-agent 体积与原生依赖不适合塞进桌面渲染进程；web-ui 已退役；无官方 React；默认无权限沙箱（编码场景假设用户自负）。

有没有非编码嵌入实例

  • 有，而且是官方点名的：OpenClaw。把 pi SDK 嵌进 WhatsApp / Telegram / Discord / Slack 等网关。文档仍写「embed an AI coding agent」，但产品是多通道个人助手，tool 集可换成 OpenClaw 自己的，不是只能 bash/edit。这是目前能核实的、最大的生产嵌入。
  • 有教程级非编码例子：Thomas Wiegold 用 SDK 做「发票进文件夹 → 校验 JSON」（文档处理），用来说明可以砍掉默认 coding tools。
  • 通道型：社区 WeChat 扩展把终端 pi session 接到微信；官方 pi-chat 做 Slack/chat。仍是「给 coding agent 换皮」，不是 Generative UI 工作台。
  • 未找到：把 pi 嵌进 Next/React/Electron、用 tool 驱动自定义渲染区的课堂/笔记产品。检索无命中则标未核实，不编造。

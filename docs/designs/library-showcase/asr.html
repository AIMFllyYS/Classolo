阶跃星辰核实结果（用户订阅，重点）

产品线完整：实时流式、一次性 SSE、同步文件、异步文件（说话人/分轨）。课堂应对准双向 WS，不要用 SSE 当麦克风真流式。

  • 实时：stepaudio-2.5-asr-stream（推荐），旧 step-asr-1.1-stream 逐步废弃。Bearer。PCM 16 kHz / 16 bit / 单声道；server_vad 或客户端 commit。
  • 文件 / 准实时：stepaudio-2.5-asr。同步路径与 OpenAI 同名：POST /v1/audio/transcriptions（multipart，file≤100MB，response_format 仅 json/text，另有 hotwords JSON 字符串）。SSE 路径 /v1/audio/asr/sse 是自有 JSON（base64 整段音频），事件名 transcript.text.delta 接近 OpenAI 文件流式，请求体不像。
  • 对话 Realtime（wss://api.stepfun.com/v1/realtime，stepaudio-2.5-realtime）是语音对话，不是转写主路径。官方 Demo 写明对 OpenAI Realtime SDK 做了修改适配。
  • 价格（模型页）：一次性/SSE 0.15 元/小时；双向流式 1.2 元/小时。Step Plan 可直接调用。与腾讯 2.0（1.0）/ 百炼北京（1.188）同量级。
  • 热词：SSE 有 hotwords[]；WS 流式用 prompt。流式文档未列出 hotwords 数组。
  • 错误码有 max_idle_timeout / pong_timeout，未写秒数。append 说明写「WAV」，session.format 写 PCM——以 PCM 实现并对照当前页，标未核实。

OpenAI 兼容是不是事实标准

  • 文件式：是。 已核实提供 /v1/audio/transcriptions（或 Groq 的 /openai/v1/audio/transcriptions）的：OpenAI、阶跃、Groq、硅基、OpenRouter。LiteLLM 把 Deepgram / Azure / Vertex / Gemini / Mistral 等也映射到同一路径。这是自定义「填 baseURL + key + 模型名」最省事的一档——但只适合课后或切片伪流式。
  • 实时 WS：不是。 完整兼容 OpenAI Realtime 转写事件+路径的，本轮只核实 OpenAI 自己。方言层：阶跃 ASR-stream、百炼 Qwen3、xAI Grok（….updated 代替 ….delta）、自托管 Speaches / vLLM（事件子集不同）。Groq、硅基官方文档没有 Realtime WS。Deepgram 是自有 /v1/listen。Fireworks 音频推理已弃用。不能把「Realtime 兼容」当成填 URL 就通的标准。

推荐设计

ASRProvider 接口与自定义配置面

业务只认统一回调。每个协议族一个 adapter；Realtime 族再加 dialect（openai / stepfun-asr / qwen3-asr），因为事件字段不能当同一套解析。

type ProtocolFamily =
  | "openai-realtime-ws"       // dialect: openai | stepfun-asr | qwen3-asr
  | "openai-transcriptions-rest"
  | "dashscope-task-ws"
  | "cloud-private-ws"         // dialect: tencent-v2 | xfyun-rtasr | deepgram-listen
  | "google-bidi"              // dialect: stt-v2-grpc | gemini-live
  | "local-engine"
  | "chunked-pseudo-stream";   // wraps openai-transcriptions-rest

interface ASRCapabilities {
  supportsStreaming: boolean;   // 边录边出 partial
  supportsHotwords: boolean;
  supportsServerVad: boolean;
  sampleRateHz: 16000 | 24000;
  idleTimeoutMs: number | null; // 文档没写则 null，实现按保守心跳
  maxSessionMs: number | null;  // 如 OpenAI Realtime 60 min
}

interface ASRProvider {
  readonly family: ProtocolFamily;
  readonly capabilities: ASRCapabilities;
  start(opts: ASRStartOptions): Promise<void>;
  sendAudio(frame: Int16Array): void;  // 已重采样到 capabilities.sampleRateHz
  stop(): Promise<void>;
  onPartial(cb: (e: { text: string; stash?: string }) => void): void;
  onFinal(cb: (e: { text: string }) => void): void;
  onError(cb: (e: { code: string; message: string; retriable: boolean }) => void): void;
}

/** 设置页「自定义接入」用户必填 */
interface CustomASRConfig {
  family: ProtocolFamily;      // 必选，禁止从 URL 猜
  dialect?: string;            // 同族方言
  baseUrl: string;             // https://api.stepfun.com/v1 或完整 wss://…
  apiKey: string;              // 只放 main，禁止进 renderer
  model: string;               // stepaudio-2.5-asr-stream / whisper-large-v3-turbo / …
  sampleRateHz: 16000 | 24000;
  extraHeaders?: Record<string, string>; // 如 OpenAI-Beta
  hotwords?: string[];
}

自定义接入怎么选族

  • 用户长期订阅阶跃 → 预置模板 family=openai-realtime-ws + dialect=stepfun-asr + baseUrl=wss://api.stepfun.com/v1/realtime/asr/stream + 模型 stepaudio-2.5-asr-stream。
  • 只给了 OpenAI 兼容网关、没有 WS 文档 → openai-transcriptions-rest，课堂自动套 chunked-pseudo-stream。
  • 百炼：选了 qwen3-asr-flash-realtime 走 Realtime 方言；选了 qwen-audio-3.0-asr-flash-streaming 走 DashScope task。两者不能混用同一 adapter。
  • 腾讯 / 讯飞：走预置 cloud-private-ws，自定义栏只改 key/引擎名，不让用户手填签名算法。

无法真流式时的降级

  • 切片 8–10 秒；若供应商最短计费 10 秒（Groq），切片 ≥10 秒，避免 5 秒片被按 10 秒收。
  • 片间 overlap 0.5–1 秒再去重；UI 按句刷新，不假装词级 partial。
  • 设置页标明「准实时，延迟约一个切片」。默认上课路径仍是腾讯 2.0 / 百炼 Qwen / 阶跃 WS / sherpa。

决策历史

  1. 2026-08-30
    AI 初步推荐 腾讯云实时语音识别 WebSocket 作 Electron 云端主方案，sherpa-onnx-node 作免 key 兜底；讯飞 RTASR 作第二云实现。理由：医疗引擎 + 请求级热词 + 无会话总时长墙 + 2026-08 文档仍在更新，且 Web Speech 在 Electron 已被 stub 为不可用。
  2. 2026-08-30
    用户反馈成本敏感、手持低价 API key，要求先比价再定。本轮结论：真流式默认改为百炼 Qwen 实时（约 1.19 元/小时）或腾讯大模型 2.0（1.00 元/小时）；小米 / OpenRouter / Groq / 硅基都不是边录边传的真流式，只适合切片伪流式，课堂主路径不值。
  3. 2026-08-30
    用户拍板默认腾讯 2.0 / 百炼 Qwen，并要求通用自定义接入（含长期订阅的阶跃星辰）。本轮结论：按协议族做 adapter（Realtime 方言 / 文件 REST / DashScope task / 云厂商私有 WS / Google 双通道 / 本地引擎）；文件式 OpenAI 兼容是事实标准，实时 WS 不是；不引 AI SDK / speechrouter / LiveKit 当接入层，自研薄 adapter；阶跃课堂走 stepaudio-2.5-asr-stream（1.2 元/小时）。
